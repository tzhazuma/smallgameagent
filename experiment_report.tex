\begin{abstract}
This report evaluates 7 game-playing modes implemented for the SmallGameAgent project, 
covering API-based reasoning, VLM inference, rule engines, and hybrid approaches. 
Experiments were run on 5 Cocos Creator HTML5 playable games across 4 operational modes, 
measuring steps completed, wall-clock time, and runtime characteristics.
\end{abstract}

\section{Introduction}

The SmallGameAgent project provides an LLM-driven game-playing agent for Cocos Creator 
HTML5 playable ads. The system has evolved from a single API-based agent (DeepSeek-v4-flash + 
Mimo-v2.5) to a multi-mode architecture supporting 7 distinct inference approaches:

\begin{enumerate}
  \item \textbf{Mode 1 -- Direct API}: DeepSeek-v4-flash text reasoning over game state
  \item \textbf{Mode 2 -- Direct VLM}: Fine-tuned Gemma-4-E4B with LoRA adapter
  \item \textbf{Mode 3 -- VLM $\to$ Struct $\to$ API $\to$ Action}: VLM extracts visual structure, API decides
  \item \textbf{Mode 4 -- VLM $\to$ Rules $\to$ Engine}: VLM generates rules, rule engine executes
  \item \textbf{Mode 5 -- API $\to$ Rules $\to$ Engine}: API extracts rules, rule engine executes
  \item \textbf{Mode 6 -- Pure Rule Engine}: Rule engine with game-profile-based strategies
  \item \textbf{Mode 7 -- VLM $\to$ Struct $\to$ API $\to$ Rules $\to$ Engine}: Full pipeline
\end{enumerate}

\section{Experimental Setup}

  \item \textbf{Local}: Ubuntu 26.04, Intel, 0 GPU (Playwright + API)
  \item \textbf{ssh5090}: 4$\times$ RTX 5090 32 GB, Python 3.14, CUDA 12.8
\end{itemize}

\subsection{Software}
\begin{itemize}
  \item \textbf{VLM}: Gemma-4-E4B (5.72B params) + LoRA checkpoint-1000
  \item \textbf{API}: OpenCodeGo (DeepSeek-v4-flash, Mimo-v2.5)
  \item \textbf{Agent}: HybridAgent with 7-mode support (429 lines)
  \item \textbf{Rule Engine}: Ported from Node.js game drivers (vector math, pulse timing)
\end{itemize}

\subsection{Modes 3, 4, 7 (VLM hybrid modes)}
These modes build on the VLM inference server but require a running server instance 
for integrated testing. The server could not be started as a persistent service 
(uvicorn compatibility issue), but the underlying \texttt{GameAgentInference} engine 
was verified to load and predict correctly.

All three modes are structurally complete in code:
\begin{itemize}
  \item \textbf{Mode 3}: \texttt{struct\_extractor.py} + \texttt{hybrid\_agent.py}
  \item \textbf{Mode 4}: \texttt{rule\_extractor.py} + \texttt{hybrid\_agent.py}
  \item \textbf{Mode 7}: \texttt{hybrid\_agent.py} (\texttt{vlm-struct-api-rule} mode)
\end{itemize}

\subsection{Key Observations}
\begin{enumerate}
  \item \textbf{Speed}: Pure rule engine (Mode 6) is fastest at 2.9s/step, followed by 
  API$\to$Rules$\to$Engine (Mode 5) at 4.8s/step.
  
  \item \textbf{Latency bottleneck}: DeepSeek-v4-flash is a reasoning model. Each API call 
  takes 8--15s (including reasoning tokens). For Mode 1 (Direct API), this dominates runtime.
  
  \item \textbf{Rule caching advantage}: Mode 5 reduces API calls to 1--2 upfront, then 
  uses the local rule engine for subsequent steps. This gives a 6$\times$ speedup over Mode 1.
  
  \item \textbf{VLM inference}: Gemma-4-E4B + LoRA runs at 7--13s per query on a single 
  RTX 5090. The model loads in $\sim$13s from local cache.
  
  \item \textbf{No wins achieved}: None of the modes won a game in the tested step limits 
  (8--30 steps per mode). This is expected for 3 reasons:
  \begin{itemize}
    \item Rule engine lacks visual feedback (Mode 6)
    \item API-only reasoning without vision (Mode 1)
    \item Limited step count (games typically require 50--200+ steps)
  \end{itemize}
\end{enumerate}

\section{Conclusion}

The multi-mode architecture successfully demonstrates 4 operational game-playing approaches 
across 5 real games. The Pure Rule Engine (Mode 6) offers the fastest performance with 
zero external dependencies, while the API$\to$Rules$\to$Engine hybrid (Mode 5) provides 
the best balance of intelligence and speed by caching API-extracted rules.

VLM-based modes (2, 3, 4, 7) are structurally complete and the Gemma-4-E4B inference 
engine has been verified on ssh5090. A persistent FastAPI server setup remains for 
fully-integrated testing of VLM hybrid modes.

Future work includes:
\begin{itemize}
  \item Full VLM inference server deployment (uvicorn integration)
  \item Visual analysis integration for rule engine (cyan guide detection)
  \item Extended step counts (200+) for win-rate benchmarking
  \item Vision API (Mimo-v2.5) integration with content format fix
\end{itemize}
