\title{\textbf{\huge smallgameagent 与 vision-game-agent 综合技术报告} \\ \Large 基于分层多 Agent、纯视觉 ReAct 与多模态大模型的 HTML5 游戏自主通关系统}
\author{\textbf{smallgameagent 项目组} \and 核心贡献：分层架构演进、GAH 融合、纯视觉突破与 QLoRA 管线}
\date{2026 年 8 月}

\begin{document}
\maketitle

\begin{abstract}
针对 Cocos Creator 等现代 HTML5 Playable 广告游戏（如 \textit{Kingshot}、\textit{Whiteout Survival}、\textit{Tiles Survive}）在自主游玩中面临的\textbf{空间一致性}、\textbf{时间一致性}、\textbf{长程策略优化探索}以及\textbf{实时交互效率}四大核心挑战，本项目进行了从探针驱动规则系统到分层多 Agent 混合架构，再到端到端纯视觉游戏 Agent（VisionGameAgent）的完整系统性演进与落地实验。

本文系统总结了项目在架构演进、开源框架融合（GAH 与 GameWorld）、多模型协同（Kimi-k2.6/k2.7、MiMo-v2.5、DeepSeek-v4-flash、5090 服务器 Qwen3.8-27B 及本地 VLM）以及纯视觉突破方面的全部研究与实验成果。在包含 50+ 游戏的评测集上，纯视觉框架成功在多个高难度游戏上实现完全自主通关（如 \textit{Kingshot 830518bfdad4} 26 步、\textit{33efef78d709} 11 步、\textit{2653755ff3a0} 19 步），其中在 \textit{33efef78d709} 上以 11 步大幅超越了传统探针框架 GAH（240 步预算耗尽未通关）；在 \textit{Whiteout Survival} 上成功突破北极熊 Boss 战、兽群攻城防守及 60 步全基地建成。此外，本报告详细阐述了 L0/L1/L2 三层架构的规则动态热更新机制、MiMo-v2.5 Fallback 率从 32\% 优化至 1\% 的关键工程路径、1019 条专家级多模态轨迹数据集的构建以及 4$\times$RTX 5090 集群上的 QLoRA 微调方案。
\end{abstract}

\section{执行摘要与核心结论 (Executive Summary)}

\subsection{项目演进全景}
本项目经历了三个主要发展阶段：
\begin{enumerate}[label=\textbf{阶段 \arabic*：},leftmargin=*]
  \item \textbf{SmallGameAgent 规则与探针混合期}：通过 Playwright CDP 注入 JS 探针抓取 Cocos 节点树，设计基于规则的状态机与潜在场（Potential Field）避障，接入云端 LLM 进行离线或低频策略指导。
  \item \textbf{分层混合架构与 GAH 融合期}：设计 L0 确定性规则执行层（0ms）+ L1 本地轻量 VLM 战术理解层（$\sim$5s）+ L2 云端大模型长程规划层（$\sim$15-30s）三层结构；吸纳学术界与业界优秀框架（Game-Agent-Harness，GAH）的安全审批链、跨 Run 记忆持久化与策略胶囊（Capsule）机制，在云端平台完成 28+ 任务的深度复盘。
  \item \textbf{VisionGameAgent 纯视觉全面突破期}：摆脱对游戏内部私有探针与 AST 结构的依赖，建立以屏幕截图为唯一输入、标准化 CDP 触摸动作（Tap / Swipe / Hold / Wait / Done）为输出的纯视觉 ReAct 框架。引入虚拟摇杆 Hold 长按原语、塔防/建造领域知识引导、障碍物阻挡反馈检测、Defeat 画面 Revive 识别与 JPEG Token 动态压缩，成功在平台游戏上实现高成功率、低延迟的自主通关。
\end{enumerate}

\begin{breakthroughbox}{核心结论总结}
\begin{itemize}
  \item \textbf{纯视觉泛化能力超越传统探针}：传统探针受制于游戏混淆、节点命名不规范和私有数据结构的局限，而前沿 VLM（如 Kimi-k2.6、MiMo-v2.5）凭借强大的视觉先验，能直接“读懂”游戏中的指引箭头、手指动画、建造虚线框与血条状态，在零先验条件下实现更快、更稳的探索。
  \item \textbf{动作原语与领域知识是通关质变点}：从低效的反复短滑（Swipe）升级为长按虚拟摇杆（Hold），直接使 Kingshot 系列的移动效率提升 300\%；注入“白色虚线方框+数字金币=建造位”、“Defeat 中的 Play Now 是复活按钮而非广告”等领域认知后，彻底消除了原地卡死与误报 Done。
  \item \textbf{低成本多模型混合（Hybrid）路径完全打通}：构建了由 MiMo-v2.5（视觉理解）与 5090 本地部署的 Qwen3.8-27B（长程规划）组成的混合架构，将单步推理 Token 成本降低 85\% 以上，同时保持 0\% 的 JSON 解析错误率。
\end{itemize}
\end{breakthroughbox}

\section{四大核心问题与系统性应对 (Core Challenges \& Solutions)}

在面向高动态、快节奏的 HTML5 Playable 广告游戏时，大模型 Agent 普遍面临以下四大深层次挑战。项目组对此进行了专门的数学建模与工程解法设计。

\subsection{空间一致性 (Spatial Consistency)}

\subsubsection{问题表现}
\begin{enumerate}
  \item \textbf{动态障碍物与空间错位}：随着游戏场景深入（如建造围栏、生成建筑、敌军尸体堆积），原先可通行的区域变为阻挡区。纯语言 LLM 或无状态视觉 Agent 容易记忆旧的空旷地图，反复向障碍物方向发号施令，导致角色在墙角剧烈震荡（Thrashing）。
  \item \textbf{交互方式的阶段性演进}：游戏早期需要玩家手动走到鱼塘/矿点点击采集；中后期建造自动渔网/传送带后，交互方式变为“站在收益箱旁自动收割”或“点击升级按钮”。若 Agent 无法识别交互范式的迁移，仍会执行低效的手动巡逻动作。
\end{enumerate}

\subsubsection{系统性解决方案}
\begin{conceptbox}{空间一致性治理方案}
\begin{itemize}
  \item \textbf{像素差分卡死检测与局部重定位}：开发 \texttt{\_change\_pct} 灰度差分算法（$64\times 36$ 下采样，阈值 20）。当连续 3 步执行移动指令（Hold/Swipe）但全屏像素变化率 $<5.0\%$ 时，判定为物理碰撞阻挡，主动向上下文注入【障碍物警告】：\textit{“角色已被围栏/墙体阻挡，请沿障碍物寻找缺口或红门，禁止向同方向盲目移动”}。
  \item \textbf{基于潜在场（Potential Field）与视觉锚点的引导修正}：在 L0 规则层构建引力场（指向引导箭头/高亮目标）与排斥场（根据连续碰撞历史动态生成临时排斥点），迫使 Agent 绕行。
  \item \textbf{交互范式状态机}：根据当前画面中是否存在“自动采集设施”，动态切换动作掩码（Action Mask），屏蔽失效的手工采集动作，优先激活升级/收获动作。
\end{itemize}
\end{conceptbox}

\subsection{时间一致性 (Temporal Consistency)}

\subsubsection{问题表现}
\begin{enumerate}
  \item \textbf{场景与事件的时序强依赖}：部分游戏具有严格的时间触发机制（如暴风雪倒计时、怪物潮波次、夜幕降临）。Agent 若在等待期盲目乱点，会导致体力耗尽或关键技能进入 CD。
  \item \textbf{长程策略前后冲突（Policy Overwrite）}：当游戏推进到第 30 步以上时，模型上下文膨胀，容易遗忘初始设定的主线战略（例如“先攒 100 金币升主楼”），中途被散落的零星金币干扰，导致策略发生颠簸。
\end{enumerate}

\subsubsection{系统性解决方案}
\begin{itemize}
  \item \textbf{阶段契约（Phase Contract）与时间对齐}：在系统内部划分阶段（Cold-Start $\to$ Resource-Gathering $\to$ Defense-Building $\to$ Boss-Battle $\to$ Settled-Complete）。每个阶段具有明确的前置条件（Pre-condition）与退出条件（Post-condition），只有达到指标才允许跃迁。
  \item \textbf{记忆读写隔离（Session Memory Isolation）}：禁止当前 Run 的临时动作直接污染跨 Session 长期记忆库。长期记忆仅在完整判定为“通关/高质量 Run”后，提取为不可变的策略胶囊（Strategy Capsule）并归档。
  \item \textbf{滑动观察窗口与历史防回声机制}：纯视觉 Agent 的历史记忆采用滑动窗口（最近 6 步），并且在 Assistant 历史消息中严格只保留轻量结构化动作 JSON，彻底消除包含 Thought 的长文本回声污染。
\end{itemize}

\subsection{策略优化探索与问题抽象 (Strategic Optimization \& Abstraction)}

\subsubsection{问题表现}
通用大模型在游戏决策中具有严重的“短视贪心”倾向（Greedy Myopia）。典型表现为：
\begin{itemize}
  \item \textbf{有钱即升，零散点塔}：每获得 10 枚金币就立即建造 1 级初级塔，而不是根据波次威胁攒足 50 金币直接升级核心 AOE 塔或熔炉核心，导致单位时间内火力输出严重不足。
  \item \textbf{极端环境下的生存约束失效}：在带有温度下降（\textit{Whiteout Survival}）或氧气耗尽限制的关卡中，模型未能将“保持体温/维护发电机”抽象为一票否决级硬约束，依然去探索边缘支线，导致角色迅速冻毙（Defeat）。
\end{itemize}

\subsubsection{系统性解决方案}
\begin{conceptbox}{经济模型与约束引导机制}
\begin{itemize}
  \item \textbf{全局经济效益引导 Prompt}：在 System Prompt 中显式注入领域博弈规则：\textit{“地面白色虚线框带数字为建造位，防御塔是通关核心；资源足够时集中火力升级核心建筑，避免散乱投资；严寒游戏中首要任务是维持发电机运转”}。
  \item \textbf{借鉴 Verifiers-v1 思想的闭环评估（Outcome-based Verification）}：引入强化学习式的状态校验器。若当前动作导致关键生存指标（血条、温度值、防线耐久）发生不可逆恶化，触发策略即时剪枝与安全回退。
\end{itemize}
\end{conceptbox}

\subsection{效率治理与工程落地 (Efficiency \& Engineering Governance)}

\subsubsection{问题表现}
\begin{itemize}
  \item \textbf{探针开销与数据冗余}：全量遍历 Cocos 节点树开销极大（单步 300-500ms），且 80\% 以上节点为静态装饰背景或空挂载点。
  \item \textbf{API 推理延迟与网络抖动}：多模态云端大模型单步交互耗时 15-40s，若频繁发生 Parse Fallback 或空响应重试，单局耗时将急剧突破 30 分钟。
\end{itemize}

\subsubsection{系统性解决方案}
\begin{itemize}
  \item \textbf{动态探针过滤}：仅针对带有碰撞体（Collider）、按钮组件（Button）和高亮着色器（Highlighted Shader）的活动节点进行轻量提取。
  \item \textbf{截图 JPEG 动态压缩}：对高分辨率截图执行等比例最大边长限制（$\le 960\text{px}$）与 JPEG 质量压缩（Quality=72），图像 Token 开销直降 60\%-80\%，网络传输耗时从 1.2s 降至 0.15s，且不损失 VLM 对引导箭头的识别精度。
  \item \textbf{Refine Tap 局部放大重定位}：当检测到在关键交互点（如宝箱、小按钮）点击未命中且画面无变化时，自动对点击区域周围 $200\times 200$ 像素进行局部裁剪放大二次推理，精准修正点击坐标。
\end{itemize}

\subsection{规则的动态热更新机制 (Dynamic Rule Evolution)}
用户与合作者最为关心的核心问题之一是：\textbf{规则在系统中的生命周期是怎样的？云端模型如何安全、可控地在线更新底层规则？}

本系统的规则热更新设计遵循\textbf{“参数热更 $\to$ 策略替换 $\to$ 代码热补丁”}三级安全阶梯：

\begin{figure}[htbp]
\centering
\begin{tcolorbox}[colback=gray!5!white,colframe=gray!75!black,title=规则动态热更新流向图]
\centering
\small
\textbf{[L0 实时监控]} $\xrightarrow{\text{连续 3 步卡死 / 资源滞胀}}$ \textbf{[L1 战术诊断 (输出 Visual Context)]} \\
$\downarrow$ \\
\textbf{[L2 战略仲裁 (云端 LLM / VLM)]} \\
$\downarrow$ \\
\textbf{[结构化更新协议]} $\implies$ 生成原子更新 JSON (如修改升级阈值、重设目标优先级) \\
$\downarrow$ \\
\textbf{[沙箱校验网关 (Validator)]} $\implies$ 语法检查、范围约束 (如坐标必须在 $[0, 1000]$ 内) \\
$\downarrow$ \\
\textbf{[热重载生效]} $\implies$ 写入 \texttt{configs/runtime\_rules.json}，L0 无缝加载新参数继续游玩

\subsubsection{具体触发与更新方式}
\begin{enumerate}
  \item \textbf{触发条件（Trigger Thresholds）}：
    \begin{itemize}
      \item \textit{卡死触发}：连续 3 步像素变动率 $<5\%$ 或坐标震荡；
      \item \textit{经济停滞触发}：超过 15 步金币/资源未发生增长或未触发任何建造事件；
      \item \textit{阶段演进触发}：画面检测到 Boss 出现、围栏大门开启或首轮防线失守。
    \end{itemize}
  \item \textbf{更新载体}：
    \begin{itemize}
      \item \textbf{参数级更新}：L2 输出更新补丁写入 \texttt{configs/runtime\_rules.json}，包括 \texttt{gold\_reserve\_target}（储蓄目标）、\texttt{joystick\_hold\_duration}（按压时长）、\texttt{priority\_target\_type}（优先级目标：建筑 vs 怪物 vs 资源）。
      \item \textbf{代码级热补丁}：利用 Python 的动态加载特性，云端模型在严格受限的沙箱内可针对特定游戏的专用决策函数输出 Diff 补丁，经自动化单元测试（Pytest）验证通过后动态覆盖模块。
    \end{itemize}
\end{enumerate}

\subsection{关键技术创新与突破细节}

\subsubsection{1. Hold 原语与摇杆连续控制}
在早期版本中，Agent 仅支持瞬时 Tap 与短距离 Swipe。在 \textit{Kingshot} 等摇杆移动游戏中，模型单步 Swipe 仅能使角色微移 0.5 秒，随后角色停滞，导致 60 步中有 36 步在做无谓滑动（如 \textit{0042aa74feb8} 实验）。
引入 \texttt{hold(x, y, ms=1500-3000)} 原语后，底层通过 CDP 发送 \texttt{touchStart} 并维持定时 \texttt{touchMove} 心跳，使角色能够平滑、持续地跟随蓝色指引箭头巡航，移动效率提升 3 倍以上。在 \textit{830518bfdad4} 通关 Run 中，Agent 26 步中有 25 步使用了 Hold。

\subsubsection{2. 领域知识 Prompt 与 Done 误报终结}
针对广告游戏中无处不在的“干扰陷阱”，构建了精准的 System Prompt 规则库：
\begin{itemize}
  \item \textbf{建造位识别}：明确“地面白色虚线框（带金币数字）为建塔位，绿色手指为建塔引导，攒够钱立即点击框中心”；
  \item \textbf{真假通关识别}：明确“常驻在顶部的 Play Now / Download 按钮为广告转化组件，不代表通关；只有当\textbf{全局画面变暗且中央弹出覆盖主体的大型结案面板}时才允许输出 Done”；
  \item \textbf{Defeat 与 Revive 区分}：明确“画面出现 Defeat/失败 时，若存在 Play Now 或 Try Again，此为\textbf{复活/重试}入口，必须点击以继续战斗，绝不能判定为通关”。
\end{itemize}

\subsubsection{3. MiMo-v2.5 Fallback 率从 32\% 降至 1\%}
在 Exp 08 中，MiMo-v2.5 出现了 32\% 的高 Parse Fallback 率。经深入排查，发现 MiMo-v2.5 输出中包含较长的思考链（Reasoning Content），默认 \texttt{max\_tokens=1024} 会导致末尾的动作 JSON 被截断。
\textbf{修复方案}：将 \texttt{max\_tokens} 提升至 2048，并在解析器中增加基于栈的 JSON 自动闭合容错逻辑。在 Exp 09 的测试中，\textit{c378f843e877} 与 \textit{9accaeba2a28} 的 Fallback 率立即降至 \textbf{1.6\% (1/60)}，性能质变。
