\section{smallgameagent 实验报告（第三轮：分层架构 + 批量框架）}

> 2026-07-20。配套：\_\_CODE\_0000\_\_（方案）、\_\_CODE\_0001\_\_（过程数据）。\\
> 本轮重点：分层多 Agent 架构、Node.js 高级逻辑移植、批量实验框架、数据采集管线。\\

\subsection{0. 一页结论}

\begin{itemize}
  \item \_\_BOLD\_0000\_\_：实现 L0 规则（每步 \textasciitilde{}0ms）+ L1 本地 VLM（每 5 步 \textasciitilde{}5s）+ L2 云端 API（每 15 步 \textasciitilde{}3s）三层决策。批量实验中 hierarchical 模式 composite=0.150，但 L1 因本地 VLM 未启动而退化为 L0+L2；L2 kimi-k2.7-code 的思考链输出导致 JSON 解析失败。\_\_BOLD\_0001\_\_：架构可行，但需要 (a) 本地 VLM 常驻 + (b) 更强的 L2 输出契约。
  \item \_\_BOLD\_0004\_\_：\_\_CODE\_0000\_\_ + \_\_CODE\_0001\_\_ 支持多游戏 × 多模式 × 多 seed 矩阵实验，自动采集逐步轨迹 JSONL。8 runs 产出 \_\_CODE\_0002\_\_ + 8 个轨迹文件 + \_\_CODE\_0003\_\_。
  \item \_\_BOLD\_0001\_\_：soft target lock（防 target thrashing）、guide-signature change detection（检测 guide 路径变化）、coin demand override（强制导航到 coin table）已移植到 \_\_CODE\_0000\_\_。但 soft lock 在 tap-guide 场景下反而降低了 tap 频率（rule composite 从 0.150 降到 0.10），已修复：tap 后释放 lock。
  \item \_\_BOLD\_0000\_\_：批量实验中 multi-bus 和 multi-bus-memory 均达 \_\_BOLD\_0001\_\_（2 seed 一致），确认记忆读回 + 总线通信的组合是当前最佳配置。
  \item \_\_BOLD\_0002\_\_：\_\_CODE\_0000\_\_ 已接入 \_\_CODE\_0001\_\_，每步写入 JSONL（player/action/keyNumbers/reason），可直接用于后续 VLM 微调。
  \item \_\_BOLD\_0000\_\_：674 passed, 0 failed, ruff 全绿。
\end{itemize}

\subsection{3. 批量实验框架（实验 G）}

\subsubsection{架构}

```\\
src/experiments/batch\_runner.py    — BatchConfig + run\_batch()\\
src/experiments/analyze\_batch.py   — 读取 batch\_results.json → Markdown 表格\\
src/experiments/exp\_batch\_matrix.py — 预定义矩阵配置（1 game × 4 modes × 2 seeds）\\
```\\

\subsubsection{使用方式}

```python\\
from src.experiments.batch\_runner import BatchConfig, run\_batch\\

config = BatchConfig(\\
games=\{"SSD\_00461P01": "/path/to/game.html"\},\\
modes=["rule", "multi-bus", "multi-bus-memory", "hierarchical"],\\
seeds=[42, 123],\\
max\_steps=30,\\
collect\_dataset=True,  \# 自动写入轨迹 JSONL\\
output\_dir="batch\_results",\\
)\\
results = asyncio.run(run\_batch(config))\\
```\\

\subsubsection{产出}

\begin{itemize}
  \item \_\_CODE\_0000\_\_：汇总所有 run 的 composite/activity/details
  \item \_\_CODE\_0000\_\_：每步 player/action/keyNumbers/reason
  \item \_\_CODE\_0000\_\_：Markdown 对比表格
\end{itemize}

\subsubsection{轨迹数据格式}

每行一个 JSON 对象：\\
```json\\
\{"player": \{"x": 2.53, "z": 12.78\}, "action": "tap", "keyNumbers": \{"\_failCount": 0\}, "reason": "tap\_guide\_dist=1.95"\}\\
```\\

可直接用于：\\
1. VLM 微调数据（next\_probe\_action / probe\_action\_effect 任务）\\
2. 离线回放分析（stall 检测、target thrashing 诊断）\\
3. A/B 对比可视化\\
